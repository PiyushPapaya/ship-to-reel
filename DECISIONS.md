# DECISIONS.md

One-line records of small choices made while building reel-bot (per CLAUDE.md).
Big architectural forks go to the user; these are the small ones I made myself.

## Phase 0 — Foundation

- **Schema validates the *resolved* spec** (all `$ref` inlined), since that's the contract `assemble.mjs` will consume; authoring-time `$ref` forms are resolved by `resolve-spec.mjs` in Phase 2, not validated here.
- **One schema file with `$defs`** rather than separate channel/brand/voice schema files; the validator retrieves sub-validators by JSON-pointer (`#/$defs/<name>`). Keeps the base plate a single source of truth.
- **voice is authored as `voice.md` with YAML front matter** (the machine-readable knobs) plus prose; the schema's `$defs/voice` validates the front matter, prose stays human context. Both checkable and readable.
- **Renamed `verboten` → `forbidden`** in the voice schema/keys, matching the English-everywhere preference.
- **`brands/projekt-a/` kept as PLAN specifies** and filled with a neutral, real-token starter brand (a copy-me template) rather than fabricating a real client's brand colors.
- **`channel.handle` is a placeholder `@your_handle`** — the real handle is a data value for the user to fill; structure and 9:16 safe-area math are what Phase 0 fixes (top 220 / bottom 320 / right 120 at 1080×1920).
- **Verification via `engine/validate.mjs` (ajv 2020, strict)** run as `npm run validate`; also enforces `min ≤ max` on every range, which JSON Schema alone can't express. Negative-tested to confirm it rejects bad input.
- **Toolchain:** ajv + `yaml` as the only devDeps; no runtime deps yet. Node ≥ 22 (24.13 present), FFmpeg on PATH (8.1.2).
- **Repo layout note:** `Downloads/Reels` lives inside the larger `Downloads` git repo (git root = `Downloads`); commits stage only `Reels/**` paths.

## Phase 1 — One local render

- **Monolithic composition** (motion-shorts style): `assemble.mjs` emits ONE standalone `index.html` (root + one clip per beat + one paused GSAP timeline). Deferred sub-compositions to later — the `timeline_track_too_dense` lint note is advisory, not an error.
- **Scenes as JS generators** (`engine/scenes.mjs`), one per beat type (hook/problem/code-diff/result/outro) + a generic fallback, rather than per-type template folders. Keeps assembly deterministic and one file; `templates/_shell/shell.html` holds the outer skeleton + brand-token CSS + persistent watermark.
- **GSAP vendored locally** (copied into `build/` by assemble) instead of a CDN `<script>` — removes the CDN-compromise/SRI vector the security hook flagged and makes renders network-independent/deterministic.
- **Watermark has no `class="clip"`** so the runtime keeps it visible the whole video (per the data-attributes contract), instead of a full-span clip.
- **Sequential scenes on one track, fade-in entrance only.** No crossfades/seams yet — those are deliberately Phase 3 (Cinematic); Phase 1 accepts hard cuts to prove the pipeline.
- **Duration model:** per-scene = `beat.dur` (number, or range resolved by `tempo.pace`: fast→min, slow→max, medium→mid) else a per-type default × pace factor; root `data-duration` = sum. `meta.duration` range is advisory in Phase 1.
- **Darkened secondary text** (`.body` #3f3f46, code file/add/del) to clear all WCAG-AA contrast warnings — the `--muted` palette token is for lines/placeholders, not body copy.
- **render.mjs uses `shell:true` on Windows** (Node ≥20 refuses to spawn `npx.cmd` directly) with defensive arg-quoting; verifies the MP4 via ffprobe (1080×1920, non-empty) rather than trusting "render succeeded".
- **Proof:** `npm run build` → `build/reel.mp4`, verified 1080×1920, 11.90s, 357 frames. Lint 0 errors, validate 0 errors + all text passes WCAG AA.

## Phase 2 — From real data

- **Ran as the main agent, no subagents** (user override for this phase — CLAUDE.md's Phase 2+ subagent guidance was explicitly skipped for this pass).
- **`collect.mjs` talks to GitHub only through `gh` via `execFileSync` with an argv array**, never a shell string — a hostile PR title or filename in the ref can't inject a command. Ref parsed with a strict `owner/repo#number` regex before any `gh` call.
- **One representative file per PR**, not the full diff: pick the largest non-lockfile change by additions+deletions, then take the first added/first removed line from its unified-diff `patch`, trimmed to 60 chars. A `code-diff` beat is a caption card, not a diff viewer — showing everything would blow the beat's duration and the schema's single-slot shape.
- **`collect.mjs` outputs display-ready strings** (`hook_line`, `problem_body`, …), not raw PR fields — keeps `archetypes/bugfix-reel/beats.json` pure data (placeholders only, no formatting logic), matching PLAN §3 ("Archetypen als Daten"). Formatting (label-joining, PR-body fallback, pluralizing "file/files") lives in `collect.mjs`, not in the template or in `resolve-spec.mjs`.
- **Placeholder syntax is `{{dot.path}}`**, resolved generically in `resolve-spec.mjs` (`fillTemplate`) against whatever tokens object it's given — not bugfix-reel-specific, so the next archetype (release-reel) reuses it unchanged.
- **`resolve-spec.mjs` re-validates the merged spec against `reel-spec.schema.json`** before returning it (same ajv-strict gate as `assemble.mjs`) — a broken merge fails loud at resolve time, not three steps later at render time.
- **`meta.duration` fixed to `"auto"`, `meta.format` defaults to `"9:16"`** (channel's layout call, per the merge rule) — no per-archetype duration math yet; `assemble.mjs` already derives real timing from `tempo.pace` + each beat's `dur` range.
- **`build/` is now fully gitignored** (was previously only `*.mp4`/`out/`/`dist/`); Phase 1's rendered HTML/PNG snapshots were untracked stragglers, not intentional check-ins.
- **Proof, end-to-end from a real merged PR** (not synthetic data): `node engine/collect.mjs anuraghazra/github-readme-stats#4709` → `resolve-spec.mjs` → `assemble.mjs` → `render.mjs` → `build/reel.mp4`, verified 1080×1920, 11.90s, 357 frames. `npm run validate` still 5/5 green (no regression on Phase 0/1 data).

## Phase 3 — Cinematic

- **Crossfade via overlap, not opacity on the clip itself.** Per hyperframes-core's rule ("never animate visibility/opacity on the clip; HyperFrames already shows/hides clips by data-start/data-duration"), each scene got a `.scene-fill` child that owns the opaque background; `assemble.mjs` overlaps consecutive scenes by a seam (`SEAM_BY_PACE`: fast 0.3s / medium 0.4s / slow 0.5s, clamped to ≤40% of the shorter neighbor) and fades the *next* scene's `.scene-fill` in from 0→1 over the seam. The still-opaque previous scene needs no fade-out — the incoming fill simply dissolves over it (verified visually via `hyperframes snapshot` mid-seam: text washes to white, then the next scene's headline rises in).
- **Overlap requires different tracks.** hyperframes rejects same-track time overlap, so scenes alternate `data-track-index` 1/2 by parity (`i % 2`). Track index is temporal-lane bookkeeping only — paint order is still DOM order, which is what makes the crossfade visible.
- **`engine/seam-gate.mjs` re-parses the assembled `build/index.html`** (never trusts `assemble.mjs`'s own math) and asserts, per adjacent scene pair: positive overlap exists, tracks differ, and a `tl.fromTo(...opacity:0...)` crossfade tween is present for the later scene. Wired into `npm run build` between `assemble` and `render` — a regression to hard cuts fails the build, it doesn't just look flat in a video nobody reviews (PLAN §5 discipline).
- **Proof:** `npm run assemble && npm run seam-gate` → 13/13 seam checks green on the 5-beat example spec; `npx hyperframes lint` 0/0; `render.mjs` → `build/reel.mp4` verified 1080×1920 (duration dropped 11.9s→10.7s, the sum of the 4 seam overlaps, as expected); `hyperframes snapshot` at 1.35s/1.45s/1.9s confirms a real visual dissolve, not just passing structural checks.

## Phase 3b — capture.mjs (real UI as base footage)

- **Capture target for `github_pr` sources is the PR's conversation page** (`github.com/o/r/pull/N`), not the "Files changed" tab. Tried `/files` first: GitHub renders it as a virtualized SPA view — `document.body.scrollHeight` stayed pinned to exactly the viewport height after `networkidle` + a settle wait, so the scroll-capture silently produced 4 byte-identical frames (caught by hashing the output, not by the script "succeeding"). The conversation page is normal document flow and scrolls as expected — verified via distinct SHA-256 hashes and increasing `scrollY` across frames.
- **No new schema field for a "capture URL".** `source.ref` (already `owner/repo#123` for `github_pr`, already a raw URL for `kind:"url"`) is enough to derive what to capture; a preview-deploy URL would need detection logic and isn't guaranteed to exist for every merged PR, so it's out of scope here.
- **Output is a standalone frame sequence + manifest** (`<out>/capture/frame-NN.png` + `manifest.json`), not yet wired into `assemble.mjs`'s beat rendering — proving the capture building block in isolation first, per PLAN §7 ("jedes Bauteil wird adaptiert... nicht copy-paste"), before deciding how a scene consumes it (background layer? dedicated `capture` beat type?).
- **`--spec` mode no-ops cleanly when `source.capture` is false** (exit 0, explicit log line) rather than erroring, since most specs won't request capture and the CLI is meant to sit in the normal pipeline.
- **Proof:** `node engine/capture.mjs --url https://github.com/anuraghazra/github-readme-stats/pull/4709 --out build/capture` → 4 frames, distinct SHA-256 hashes, `scrollY` 0/85/170/255; `--spec` mode verified both branches (capture:false → skip, capture:true → same 4-frame capture). `npm run validate` still 5/5 (no regression).

## Phase 4 — Waechter (quality-check.mjs)

- **Ran as the main agent, no subagents** — same call as Phase 2: this is one cohesive gate script, not parallelizable work, and no `.claude/agents/` Sonnet-pinned definitions exist yet in this repo to delegate to.
- **Split into a fully-automated functional gate and a scored-but-not-automatable aesthetic gate**, rather than faking one combined score. No vision-model API is wired into this repo, so `quality-check.mjs` cannot see its own frames — it extracts them (`ffmpeg -vf fps=2`) and writes a scorecard scaffold; the actual aesthetic judgment is made by whoever is driving the build (agent or human) reading `build/quality/frames/*.png` and writing `--scores <path.json>`. The gate enforces the *threshold* mechanically (avg ≥ 4.0, every one of 7 dimensions ≥ 3 — deliberately harder than pitchkit per PLAN §5) so a future CI run can't rubber-stamp a flat render just because nobody looked.
- **Functional pass reuses `hyperframes lint`** (already proven in Phase 3) rather than re-implementing clip/overflow checks, then adds three checks specific to *this* repo's known failure modes: ffprobe dims/duration (never trust exit code), and frame-hash uniqueness to catch a frozen render — the exact bug `capture.mjs` hit in Phase 3b (4 byte-identical "different" frames), generalized into a reusable check instead of a one-off fix.
- **Not wired into `npm run build`.** Functional checks are cheap and could be, but the aesthetic gate needs a human/agent scoring pass first — forcing it into the default build chain would either block every build on manual scoring or silently no-op the aesthetic half, both worse than a separate `npm run quality-check` step run deliberately.
- **Proof, real (not synthetic) scores:** ran `quality-check.mjs` against the actual `build/reel.mp4` from Phase 2/3 (bugfix-reel, PR #4709). Functional: 5/5 green (0 lint errors, 1080×1920, 16/21 unique frames — not frozen). Aesthetic: read the extracted frames directly and scored honestly — avg 2.57/5, below the 4.0 threshold, exit 1. This is the *correct* result, not a bug: content sits in a cramped lower-middle band with huge unused vertical space, motion is fade-only (no translate/scale/parallax), palette is thin, and `capture.mjs`'s frames from Phase 3b still aren't composited into any scene. The gate did its job — caught real flatness instead of trusting "render succeeded". A patch pass (background layer / motion depth / capture compositing) is follow-up work, not done this pass.
- **Threshold-fail test (`avg 2.71`, synthetic scores) run first** to prove the gate's fail path exits non-zero before trusting it against real data — same "verify the checker, not just the render" discipline as `render.mjs`'s own ffprobe check.

## Phase 4b — aesthetic patch pass (follow-up to Phase 4's 2.57 fail)

- **Depth is a real DOM node (`.bg-depth`), not a `::before` pseudo-element**, added structurally by `assemble.mjs` (not `scenes.mjs`, which stays pure data→markup) — GSAP can't animate a pseudo-element, and the whole point of this pass is a parallax drift, not just a static gradient.
- **Hook scene composites Phase 3b's `capture.mjs` output** (`<outDir>/capture/manifest.json` → first frame) as its `.bg-depth` background image + a `.scrim` gradient for text legibility, wired directly in `assemble.mjs`'s clip-building loop — this is the "wiring capture into a scene" step Phase 3b deliberately deferred, done here for the one scene it makes sense for (hook = the real-UI moment). Other scenes keep the plain radial-gradient depth (no UI screenshot fits there).
- **Motion got a second, independent tween**: `.bg-depth` drifts+scales across the *whole* scene span (`tl.fromTo(...duration: dur+seam...)`) separately from the content's fade+rise+scale entrance — addressing Phase 4's specific complaint ("only motion is opacity fade-in, no translate/scale/parallax") without touching the seam-gate-verified crossfade tween.
- **Re-scored honestly against the same 7-dimension rubric**, not adjusted to pass: avg moved 2.57 → 3.71 (typography/color/hierarchy/consistency/motion_flow each +1, composition/distinctiveness unchanged) — genuine improvement, still correctly below the 4.0 threshold. `quality-check.mjs --scores` still exits 1. Composition/distinctiveness need a real layout restructure (where content sits, not just what's behind it) — tracked as further follow-up, not done in this pass to avoid overfitting the score instead of the actual video.
- **Proof:** `npm run assemble && npm run seam-gate` → 13/13 (unchanged, crossfade contract untouched); `npx hyperframes lint build` → 0/0; `render.mjs` → `build/reel.mp4` verified 1080×1920, 10.7s; `quality-check.mjs build build/reel.mp4` functional 5/5; `--scores build/quality/scores.json` → aesthetic avg 3.71 (up from 2.57), every dimension ≥3, still correctly exits 1 at the avg≥4 gate.

## Phase 3c — align-captions.mjs + tts.mjs + beat-sync.mjs (unblocking the earlier deferral)

- **TTS provider is Edge-TTS (`msedge-tts`) by default, ElevenLabs only if `ELEVENLABS_API_KEY` is set** — the "keyless -> key" fallback chain PLAN §11 calls for. Both return the same shape (`{audioPath, words, duration, provider}`) so `align-captions.mjs`/`assemble.mjs` never branch on provider. Edge-TTS's own word-boundary metadata gives exact per-word timestamps for free (Offset/Duration in 100ns ticks); ElevenLabs' `/with-timestamps` endpoint gives character-level alignment instead, so `tts.mjs` groups characters into words on whitespace to normalize both providers to the same word-timestamp shape.
- **No new "script" field.** The spoken text for a beat is the same visible copy `scenes.mjs` already renders (stripped of HTML tags), not a separately authored narration script — this makes narration and captions agree by construction and needed zero schema changes. A real product call, not a shortcut: a divergent script would need its own authoring/schema surface this pass doesn't need.
- **A beat's on-screen duration is raised to fit its narration** (`max(pace-based duration, narration length + 0.4s)`) when `<outDir>/narration/manifest.json` exists — otherwise scenes cut away mid-sentence. Silent builds (no `tts.mjs` run) are completely unaffected; this is read-and-branch, not a required step.
- **Narration audio is muxed as real `<audio id="..." class="clip" data-start data-duration data-volume="1">` elements**, one per beat, discovered via `npx hyperframes docs data-attributes` (`data-volume`/`data-media-start` are documented render-time media attributes). First attempt omitted the `id` attribute and `hyperframes lint` caught it immediately: `media_missing_id` — "this audio will be SILENT in renders." Fixed before it ever reached render.mjs; verified afterward via `ffprobe` showing a real `aac` stream matching video duration, not just "render succeeded."
- **Captions are chunked into short rolling lines (≤5 words / ≤26 chars), not one static block of the whole transcript.** The first implementation rendered all of a beat's words as one wrapped paragraph — `hyperframes snapshot` caught it visually overlapping that beat's own `<h1>` headline (the "problem" beat's 12-word transcript sat directly on top of "ci: revert restoring e2e test workflow"). Fixed by chunking words into lines that cross-fade via per-chunk `opacity` tweens (only one `.cline` visible at a time), keeping the existing per-word highlight tweens scoped inside each chunk. Re-verified via `hyperframes snapshot --at` at three timestamps — captions now sit as a short line below the headline, never overlapping it.
- **A silent `tl.set` selector-quoting bug** (`"#id .cw[data-i="0"]"` — double quotes inside a double-quoted JS string literal) was caught by actually running `hyperframes lint` after generation, not by "the code looks right." Fixed by single-quoting the attribute selector. Lesson reinforced: every generated-JS string needs its quoting checked against a real lint pass, not eyeballed.
- **Captions are frame-relative, nested inside each scene's own `.scene-fill`**, not a global overlay — they show/hide automatically with that scene's existing `data-start`/`data-duration` clip lifecycle. This is a deliberate architectural choice: it reuses the same "clip owns its own visibility" contract as everything else in this repo instead of inventing a parallel global-overlay timeline. Position/size come from `channel.captions` (channel wins layout per PLAN §1's merge rule); the accent highlight color is the brand token already in `:root`.
- **`assemble.mjs` now writes `build/timing.json`** (resolved `{index, id, type, start, duration, seam}` per beat) so `align-captions.mjs` (and future `beat-sync.mjs` wiring) never re-derive the pace/seam math — one source of truth for "when does beat N actually start."
- **`align-captions.mjs`'s CLI checks for `narration/manifest.json` *before* touching any spec path.** First version read `<buildDir>/reel-spec.json` unconditionally, which crashes on the *default* `npm run build` chain (no `resolve-spec.mjs`/`tts.mjs` ever ran, so neither narration nor `build/reel-spec.json` exist). Fixed order: check narration existence first and no-op cleanly (same pattern as `capture.mjs`'s `--spec` no-op) before ever resolving a spec path.
- **`beat-sync.mjs` promotes the interrupted Phase 3c scratch attempt** (`build/audio-analysis/estimate-bpm.mjs`, energy-onset + autocorrelation BPM estimate over raw PCM) into a real module, plus a pure `snapBoundariesToBeat` function. **Deliberately NOT wired into `assemble.mjs`'s actual cut timing this pass** — there is no real music-bed asset in this repo, and sourcing one is a licensing/style call out of scope here (same class of deferral as broll/Phase 7, not a shortcut). Proven in isolation instead, same discipline as Phase 3b's `capture.mjs`.
- **Proof:** `tts.mjs` word-boundary timestamps verified directly (`Hi`/`how`/`are`/`you`/`doing`/`today` at correct offsets) before wiring into the pipeline. Full real-data run: `collect.mjs` (PR #4709) -> `resolve-spec.mjs` -> `capture.mjs` -> `tts.mjs` (5 beats, 26.35s narration) -> `assemble.mjs` (27.2s, up from 10.7s silent) -> `seam-gate.mjs` 13/13 -> `align-captions.mjs` (5 beats, 49 words) -> `hyperframes lint` 0/0 -> `render.mjs` -> `build/reel.mp4` verified 1080x1920, 27.2s by `ffprobe`, **with a real `aac` audio stream** -> `quality-check.mjs` functional 5/5 (54/54 unique frames). `beat-sync.mjs` verified against synthetic click tracks: 128bpm click estimated at 130.1bpm, 90bpm click at 90.7bpm (both within ~2%); `--snap-test 120` correctly snaps `[0, 3.5, 7.2, 11]` to `[0, 3.5, 7, 11]`. `npm run validate` still 7/7 after adding the optional `tempo.bgm` schema field.

## Phase 4c — composition layout restructure (follow-up to Phase 4b's 3.71)

- **`.stage` moved from `justify-content: center` to a top-anchored rule-of-thirds layout** (`justify-content: flex-start; padding-top: 9%`) for hook/problem/code-diff — the actual root cause of Phase 4b's "composition" complaint: a short text block centered inside a 1380px-tall safe area just floats in a mostly-empty box no matter how much depth/color sits behind it. `result`/`outro` deliberately keep the old centered layout (`[id$="-result"] .stage, [id$="-outro"] .stage`) — they're short "reveal" beats where a big centered metric/sign-off is the right read, not a defect to fix.
- **A real per-beat ghost index numeral** (`assemble.mjs` emits `<div class="stage-index">01</div>` etc., `01`-padded, ~640px, bleeding off the bottom-right corner) fills the space the top-anchor now leaves open below the text — a structural layout element decided by real beat position/count, not a decorative afterthought. Skipped on `result`/`outro` (would clash with their own already-large centered content) and on the hook scene when it's using Phase 3b's capture footage (that's already this scene's distinctive element; stacking a giant numeral over a real screenshot would clutter it).
- **Verified via `hyperframes snapshot --at` (5 timestamps) before committing to a full render** — cheaper iteration loop than a full render + quality-check per attempt. First timestamp choice (1.5s) accidentally landed mid hook→problem crossfade and looked broken (blank frame); re-picked stable mid-scene timestamps and confirmed the real layout, not a rendering bug.
- **Re-scored honestly, not inflated to clear the gate:** composition genuinely moved 3→4 (a real structural fix — content now spans the frame with intent). distinctiveness stayed at 3 on purpose: the numeral is a real, consistent motif, but the overall look is still a fairly generic "clean SaaS launch" template outside the hook's capture footage — inflating this to 4 to cross the 4.0 line would be exactly the kind of gate-gaming PLAN §5 warns against. avg = 3.71 → 3.86, still correctly below the 4.0 threshold. Real distinctiveness needs an actual brand-specific visual signature (not just a numeral) — tracked as further follow-up.
- **Proof:** `seam-gate.mjs` 13/13 (layout change didn't touch the seam/crossfade contract), `hyperframes lint` 0/0, full real-PR run (collect → resolve-spec → capture → tts → assemble → align-captions → render) verified 1080×1920, 27.2s, real `aac` audio track; `quality-check.mjs` functional 5/5, aesthetic avg 3.86 (up from 3.71), every dimension ≥3, still correctly exits 1 at the avg≥4 gate.

## Phase 5 — CI + Multi-Brand

- **Ran as the main agent, no subagents** — same call as Phases 2/4: one cohesive CI file plus one new data folder, not parallelizable, and still no `.claude/agents/` Sonnet-pinned definitions exist to delegate to.
- **Frische-Check done before copying anything** (CLAUDE.md requirement): confirmed via `gh api` that `heygen-com/hyperframes` still exists and its `.github/workflows/ci.yml` still installs FFmpeg the same way (`sudo apt-get update -qq && sudo apt-get install -y --no-install-recommends ffmpeg`, verified at two call sites in that file) — copied that exact pattern instead of trusting `reel-bot-teardown.md`'s July 2026 snapshot blindly. `actions/checkout` / `setup-node` / `upload-artifact` SHAs pinned by resolving the current `v4` tag via `gh api repos/<owner>/git/refs/tags/v4`, not guessed — `setup-node`/`upload-artifact` SHAs matched hyperframes' own pins exactly, confirming the resolution method.
- **`reel.yml` only fully builds the merged-PR / `bugfix-reel` path.** `release: published` is wired as a trigger (per PLAN §6) but every render step is guarded with `if: github.event_name == 'pull_request'` and the release branch just logs a `::notice::` no-op — there is no `release-reel` archetype or release collector yet (same honest-deferral pattern as Phase 3c), so faking a release render would just be wrong output nobody asked to see.

- **Quality gate in CI is functional-only** (`quality-check.mjs` with no `--scores`) — the aesthetic pass needs a human/agent looking at extracted frames (Phase 4 decision), which a GitHub Actions runner can't do; forcing a fake score in CI would defeat the gate's whole purpose.
- **Slack notify degrades to a warning, not a failure**, when `SLACK_WEBHOOK_URL` isn't set — Stufe 1 (PLAN §6) is "artifact + Slack", and a missing webhook secret shouldn't fail an otherwise-successful render/upload.
- **Second brand (`brands/projekt-b/`) is deliberately a strong contrast to projekt-a**, not a palette-swap — dark/warm vs. light/blue, editorial/first-person-plural voice vs. dry/technical/second-person — so a real regression (e.g. `resolve-spec.mjs` silently falling back to projekt-a's tokens) would be visually obvious, not just schema-valid.
- **`engine/validate.mjs` changed from hardcoding `brands/projekt-a` to discovering every `brands/<slug>/` folder via `readdirSync`.** The old hardcoded case list couldn't have caught a broken second brand folder at all — a validator that only proves the one brand it was written against isn't proving the scaling claim.
- **Proof:** `npm run validate` → 7/7 (schema + example + channel + both brands' `brand.json`/`voice.md`). Full render with `--brand projekt-b` on the same real PR tokens from Phase 2 (`anuraghazra/github-readme-stats#4709`): `resolve-spec` → `assemble` (5 scenes, 10.7s) → `seam-gate` 13/13 → `render` → `build/projekt-b/reel.mp4` verified 1080×1920 by ffprobe → `quality-check` functional 5/5 (0 lint errors, not frozen). Extracted frame visually confirmed: dark paper/orange accent (not projekt-a's white/blue), distinct voice copy on the hook card. `reel.yml` parsed clean with the `yaml` package (no `actionlint` binary available locally to lint further); no `.github/workflows/` existed in this repo before this pass.

## Phase 6 — Distribution (`generate-distribution-copy` + gated `distribute/`)

- **Ran as the main agent, no subagents** — same call as Phases 2/4/5: still no `.claude/agents/` Sonnet-pinned definitions exist to delegate to, and this is one cohesive slice (a copy generator + three small platform modules sharing one env-gate helper), not independently parallelizable work.
- **User confirmed no distribution API credentials exist yet** (asked directly — a real architecture fork per CLAUDE.md, since it decides whether posting can be live-tested or only built to a safe no-op boundary). Chose to build both halves: `generate-distribution-copy.mjs` fully real and testable (no keys needed), `distribute/*.mjs` posting scripts scaffolded and env-gated, matching Phase 5's Slack-webhook degrade pattern exactly (missing config -> log + skip + exit 0, never a hard failure).
- **`voice.lexicon`/`voice.forbidden` are `oneOf` string|structured per the schema** (free text is human guidance, not machine-parseable) — `generate-distribution-copy.mjs` only acts on the structured map/array shape and no-ops on free text, rather than trying to parse prose.
- **Forbidden words are a hard gate, not a silent strip** — `applyVoice()` throws if a forbidden word survives lexicon substitution, same "gate, don't quietly patch" discipline as `seam-gate.mjs`/`quality-check.mjs`. A forbidden word appearing means the *source token* (PR title/body) is wrong, not that the copy generator should mangle it and hide the problem.
- **No new schema fields.** Distribution copy is derived entirely from the already-resolved `reel-spec.json` (`channel.handle`, `voice.lexicon`/`forbidden`) plus `tokens.json` (`pr.title/url/labels`, `hook_line`, `problem_body`, `result_metric`) — the same tokens `archetypes/bugfix-reel/beats.json` already consumes, so this phase needed zero changes to the base plate.
- **Instagram posting requires a publicly reachable video URL** (Graph API's `media_type: REELS` container can't take a local file) — `instagram.mjs` takes `IG_VIDEO_PUBLIC_URL` as a required env var rather than trying to host the MP4 itself; documented in `distribute/README.md` as a prerequisite (e.g. point it at the CI artifact URL).
- **Posting defaults lean private** (`YT_PRIVACY_STATUS=private`, `TIKTOK_PRIVACY_LEVEL=SELF_ONLY`) so the first real run with real credentials can't accidentally auto-publish publicly.
- **`distribute/` is deliberately NOT wired into `reel.yml`** — PLAN §6 calls Stufe 2 "später"/manual, and none of the three posting flows have been exercised against a live account (see below), so auto-triggering them from CI would be worse than not having them.
- **Live posting is honestly unverified.** `youtube.mjs`/`instagram.mjs`/`tiktok.mjs` are written against each platform's currently-documented flow (resumable upload / container+publish / FILE_UPLOAD init+PUT) but never called against a real account — no credentials exist in this repo or session. This is flagged explicitly in `distribute/README.md` as a Frische-Check the user must do (re-verify endpoint version/limits) before the first real run, not silently presented as tested.

## ROADMAP-NEXT.md 1.1 — score-frames.mjs (automated aesthetic scorer)

- **Ran as the main agent, no subagents** — one cohesive script plus a small `quality-check.mjs` wiring change, not parallelizable.
- **Raw HTTP against the Messages API, no `@anthropic-ai/sdk` dependency** — matches this repo's existing convention for every other external API call (`broll.mjs`: Veo/Sora/Runway/Kling; `tts.mjs`: ElevenLabs/Edge-TTS), all of which are hand-rolled `fetch` calls with zero SDK deps. Adding a new npm dependency for one script would break that consistency.
- **Model is `claude-opus-5` by default** (`SCORE_MODEL` env override) — this is an LLM-as-judge task where honest scoring quality matters more than per-call cost, and the roadmap's own fork note says to cap *frame count*, not reach for the cheapest model.
- **Sampling capped at 6 frames by default** (`--max-frames`), evenly spaced across the full extracted set — bounds token/cost per render regardless of clip length, per the roadmap's explicit fork callout.
- **`--auto` on `quality-check.mjs` degrades to the existing "pending" aesthetic state on any failure** (missing key, API error, malformed response) rather than failing the build — same best-effort discipline as `broll.mjs`/`distribute/*.mjs`. A machine with no `ANTHROPIC_API_KEY` configured still finishes clean, exactly like before this change.
- **Caught and fixed a stale-file bug during verification**: the first `--auto` implementation checked `existsSync(autoOut)` after invoking `score-frames.mjs` to decide whether scoring succeeded, but a prior manual `--scores` run had already left a `scores.json` on disk — so a *skipped* score-frames run (no API key) silently reused yesterday's numbers instead of falling back to pending. Fixed by deleting `autoOut` before invoking the scorer, so `existsSync` can only be true if this run actually wrote it. Caught by actually running `--auto` twice (once after a manual `--scores` run) and reading the output, not by reasoning about the code.
- **Explicitly not done this pass**: the roadmap's "then the loop" half of 1.1 — auto-patching `assemble.mjs`/`scenes.mjs` knobs on a failing score and re-rendering until ≥4.0. That's a materially larger scope (deciding *which* knob maps to *which* weak dimension) and is tracked as further follow-up, not silently folded in here. This pass ships the scorer and its wiring into the existing manual gate, honestly labeled.
- **Proof:** `node engine/score-frames.mjs build/quality/frames --out <tmp>` with no `ANTHROPIC_API_KEY` set → clean `{"status":"skipped","missing":["ANTHROPIC_API_KEY"]}`, exit 0, no file written. `node engine/quality-check.mjs build build/reel.mp4 --auto` → same clean skip → falls back to pending aesthetic state, functional 5/5, exit 0 (no regression from before this change). Manual `--scores <path.json>` path re-verified unaffected: synthetic all-4s scores → avg 4.00, 7/7, exit 0. `npm run validate` still 7/7 (no schema changes this pass).

## ROADMAP-NEXT.md 1.3 — composite resolved broll[] clips into scenes

- **Ran as the main agent, no subagents** — one contained change to `assemble.mjs` plus two CSS rules in `templates/_shell/shell.html`, not independently parallelizable.
- **The hyperframes media contract forced the actual design**: `<video>`/`<audio>` must be a direct child of the composition root — never nested inside a wrapper `<div>` — or the runtime never decodes/seeks it (confirmed via `hyperframes-core`'s `variables-and-media.md` / composition-patterns.md archetype B, *not* assumed). So a resolved broll clip is emitted as its own root-level `<video class="clip">`, placed in DOM order immediately before its matching `<section>` scene — the same DOM-order stacking the scenes already rely on for their own crossfade — rather than nested inside `.scene-fill`/`.bg-depth` like the capture screenshot is.
- **`.scene-fill` gets a `scene-fill-broll` modifier (`background: transparent`) only for beats with a resolved broll clip** — its normal opaque `var(--paper)` background would otherwise fully occlude the sibling video sitting behind it in the stacking order, regardless of nesting depth. `.bg-depth`'s gradient tint and `.scrim` still render as descendants of `.scene-fill`, so they composite on top of the video exactly like they do over the capture screenshot.
- **Capture wins if a beat has both** a capture screenshot and a matching broll item — capture is real UI footage, broll is the abstract/generative fallback; the roadmap frames broll as an ingredient for beats capture doesn't cover.
- **One dedicated `data-track-index` per broll video** (`BROLL_TRACK_BASE + beat index`, from 20), not a shared track — avoids ever hitting hyperframes' same-track-overlap rejection regardless of seam adjacency between beats, without needing to reason about which beats' windows might overlap.
- **Matched by `beat.type`** (`broll[].at`) — this schema's beats have no `id` field, only `type`, so `beat.id` matching mentioned in the schema's own description is a no-op here until beats gain ids.
- **Proof:** built a local mock clip (`ffmpeg testsrc2`, no video-gen credentials needed) with a hand-written `broll/manifest.json` (`status: "resolved"`) attached to `at: "problem"` against `examples/reel-spec.example.json` (whose own committed broll item targets `hook`, deliberately used a different beat to isolate from a leftover capture-manifest hook screenshot in `build/` and prove capture-wins-priority separately). `assemble.mjs` emitted the `<video id="scene-1-problem-broll" class="clip bg-broll-video" ...>` at the correct start/duration/track, `seam-gate.mjs` 13/13 (unchanged — video insertion doesn't touch the scene-overlap contract), `hyperframes lint` 0 errors, `hyperframes validate` 0 errors. `hyperframes snapshot --at 2.5,3.0` visually confirmed real per-frame video motion (the testsrc2 motion graph's dot/line moved between the two timestamps) correctly composited behind the scrim and stage content.
